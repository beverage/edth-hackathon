# Decisions

One line each, numbered, newest last.

1. Repo lives in `~/Code/Apps/edth-hackathon` (Alex, section 10), pushed to the private GitHub repo `beverage/edth-hackathon` on Alex's go-ahead.
2. No Vercel team called `edth-hackathon` exists on the account, so the project `edth-hackathon` is deployed under the only team, "Beverage" (`beverage2`). Move it when a team exists.
3. Next.js 16.4.6 from `create-next-app`, App Router, TypeScript, no Tailwind (plain CSS keeps the page small), npm.
4. Removed `cacheComponents` and `partialPrefetching` from the scaffolded `next.config.ts`; the app is one client page plus one dynamic POST route and needs neither.
5. MapLibre GL v6 loads its worker from `import.meta.url`, which the Next bundler rewrites; `scripts/copy-maplibre-worker.mjs` copies the worker to `/public` before dev and build, and the app calls `setWorkerUrl`.
6. Map style is OpenFreeMap `https://tiles.openfreemap.org/styles/liberty` (checked on openfreemap.org quick start, 20 Nov); attribution shown uncompacted.
7. Speech-to-text model is `voxtral-mini-transcribe-3`, not `voxtral-mini-latest`: the current Mistral docs recommend it and `voxtral-mini-2602` (behind `-latest`) is past its 31 Oct 2026 deprecation date. Overridable with `MISTRAL_STT_MODEL`.
8. Extraction model is `mistral-small-latest` with `response_format: json_schema` (strict). Measured on 20 Nov: 0.55-0.85 s and more accurate than `ministral-8b-latest` (0.75-1.3 s). Overridable with `MISTRAL_EXTRACT_MODEL`.
9. Mistral STT verified live with m4a (iOS) and webm/opus (Android): both accepted, ~0.3-0.9 s for a 3 s clip. `return_language=true` returns the detected language.
10. `context_bias` is sent as a repeated multipart field, capped at 100 terms (150 were accepted; 100 was the old documented cap). Terms are ordered stations, castle, town halls, churches, police, hospitals, bridges, parks, other POIs, major streets.
11. Gazetteer box S 48.835 W 2.410 N 48.856 E 2.460 as briefed; 889 features (6 stations, 11 churches, 2 town halls, 1 castle, 464 streets). Duplicates (same name and category within 300 m) are merged; streets are merged by name and keep their polylines.
12. RER "Vincennes" is in `metro_station` (subtype `rail`): the intent schema has no separate rail category, and people say "the station" for both.
13. Only Christian places of worship are `church`; others are `other` with a subtype, so "the church" never offers a synagogue or Kingdom Hall.
14. Name matching: canonical tokens (accents folded, st→saint, street/road→rue, church→eglise, castle→chateau), score = 0.6 recall + 0.25 precision + 0.15 contiguous phrase; good match ≥ 0.7 and within 0.1 of the best. An exact name match drops partial ones ("Châtelet du Château de Vincennes").
15. A category narrows a shared name only when a category word is said outside the name (checked deterministically on the transcript), so "the château de Vincennes" stays ambiguous and "the Château de Vincennes metro station" resolves.
16. A name said as only category words ("the church", "la mairie") is treated as a category search, whatever the model returns.
17. A name not in the gazetteer with a category falls back to asking among that category; it never auto-resolves.
18. Each candidate carries its own precomputed placement (pin, radius, heading), so tapping a choice needs no second server call.
19. Streets: pin is the point on the street nearest the last position; with no last position, the street's middle vertex with a radius of half its extent (max 400 m). Parks and the château use their own extent (max 500 m) as minimum radius.
20. "Towards" with no last position draws only a target ring, since there is no origin for an arrow.
21. A movement report does not refresh the last-position timestamp: the speaker's location is not newly known.
22. Mic is released after each clip so iOS plays the spoken question through the speaker, not the earpiece. Cost: a short mic start-up on each press.
23. Hold-to-talk with a 400 ms threshold; a shorter tap (or a release during the permission prompt) switches to tap-to-stop. Clips under 350 ms are discarded.
24. Rate limit is per serverless instance, 30 requests per minute per IP; good enough for stage 1, not a security control.
25. Vercel function region pinned to `cdg1` (Paris) so phone → function → Mistral stays in Europe.
26. Local dev uses port 3117 because port 3000 is taken on Alex's machine.
27. Ukrainian speech output will use the Piper voice `uk_UA-ukrainian_tts-medium` (CC0, 77 MB; speakers lada, mykyta, tetiana): Alex, 20 Nov, after hearing sample clips ("much better"). Not wired in yet, so questions still use `speechSynthesis`. The model is in `models/piper/`, ignored locally and not in the repo. Open: which speaker, where it runs, and whether its stress marks work (a rough check was inconclusive). Piper's own engine is GPL-3.0; Claude's proposal is to run the model through onnxruntime (MIT) instead.
28. Central Kyiv is a second area next to Vincennes, not a replacement: each area has its own gazetteer file, the page has a Vincennes / Київ switch, `?area=kyiv` opens Kyiv directly, and `/api/report` takes an `area` field (default `vincennes`).
29. Kyiv box S 50.428 W 30.485 N 50.472 E 30.565 (main railway station to the Lavra, Olimpiiska to Podil): 2,112 features (26 stations, 67 churches, 317 streets, 7 bridges, 5 "town halls", which in Kyiv are the city administration and ministries).
30. Gazetteer names now also keep `name:uk`, `name:ru`, `int_name` and a Latin transliteration of the Ukrainian name (official 2010 system), so "Khreshchatyk" matches where OpenStreetMap has no English name.
31. The name normaliser keeps any script: Cyrillic is kept as written (й and ї are not folded), only Latin accents are folded, and apostrophes inside Cyrillic words are dropped.
32. Ukrainian case endings: the extractor also returns `landmark_name_lemma`, the name in dictionary form ("Софійського собору" → "Софійський собор"). It is a spelling normalisation of what was said, never a new place. The resolver searches both forms, and two Cyrillic words count as the same if their first four or more letters agree and only endings of up to three letters differ.
33. Ukrainian (and common Russian) category words are matched by stem plus case ending ("церкви", "мостом"). "міст" (bridge) is matched exactly only, because "міста" means "of the city".
34. Streets are also indexed without their street word, because people say "на Хрещатику", not "на вулиці Хрещатик". A street and a station of the same name are then both exact matches, and the app asks which.
35. Same-name matches within 120 m of each other (or one inside the other), neither larger than 300 m, are one place: they fold into one candidate and the circle widens to the largest of them. Examples: Bérault station and Place Bérault; Maidan Nezalezhnosti station, square and street. A long street never folds into its station.
36. When no name matches and the spoken name includes type words ("станція метро Хрещатик"), the type words are dropped and only places of that type are searched, so "Gare du Nord" cannot land on "Rue du Nord".
37. Speech-to-text language is not pinned in Kyiv. With the 100 Ukrainian bias terms, short Ukrainian clips stopped coming back as Russian in tests (20 Nov, synthetic voice) and an English clip was still transcribed correctly. The language Mistral reports is unreliable with bias terms (the English clip was reported as `uk`), so the question language comes from the extractor.
38. Language is `en`, `fr` or `uk`. A report in Russian is answered in Ukrainian.
39. Interface text (buttons, status lines, choice subtitles) stays English in stage 1; only the question and the place names are in the speaker's language.
40. Questions name the kind of an "other" place from its OpenStreetMap subtype ("Золоті ворота (театр)"), instead of a generic "(place)".
41. Bias-term order is now stations, castle, town halls, bridges, major streets, churches, parks, police, hospitals, other places (replaces the order in decision 10): street names are what speech-to-text most often gets wrong.
42. Removed the ElevenLabs speech-to-text fallback: it was never exercised, and ElevenLabs is a Delaware corporation whose default endpoint is not EU-resident, which does not fit an all-European pipeline. Speech-to-text now needs `MISTRAL_API_KEY`.
43. Ukrainian speech runs in the browser: speaker tetiana, onnxruntime-web 1.31.1 (WebAssembly, one thread), plain text with stress marks removed (Alex, 20 Nov; settles the open points of decision 27). The code is `lib/tts/` and `/tts-lab` is its test page. It is not hooked into the app's questions yet. In desktop Chromium it produced the same audio as Piper for four reference sentences and made 4.5 s of speech in about 0.85 s; phones are unmeasured.
44. Piper's GPL engine is not used. `lib/tts/ukrainianText.ts` is our own text handling (lowercase, decomposed letters, a pad between symbols), checked against Piper's output in `tests/tts.test.ts`. Text with characters the voice lacks (digits, Latin, Russian-only letters) is declined, so the caller can use the system voice.
45. onnxruntime-web is loaded from `/public/ort` at run time, not bundled (same reason as decision 5). `scripts/prepare-tts.mjs` copies it and puts the 77 MB model in `/public/tts`; both are ignored by git. The model is checked against a pinned SHA-256 and kept in the browser's Cache Storage. On Vercel the model is left out unless `TTS_BUNDLE_MODEL=1`, and a browser download from Hugging Face is off unless `NEXT_PUBLIC_TTS_HF_FALLBACK=1` because it is US-hosted (see decision 42). Open: how production gets the model.
46. A movement report now moves the marker (replaces decision 21 and the brief's "towards keeps the pin"): Lysk's deck says the marker moves on "I moved towards 35th street". The report gives a direction, not a distance, so the marker goes to the middle of the leg from the last position to the target (for a street, its nearest point) and the circle is half the leg (50 m at least), spanning from where they were to the target. The arrow stays. With no last position only the target ring is shown (decision 20 stands).
47. A position that came from a movement report is an estimate: its time label starts with ≈ and it is sent back as `lastPosition` with `uncertainty_m`. "Nearest wins" then has to hold in the worst case: nearest + u < 0.4 × (second − u). Stated positions carry no such term, so their behaviour is unchanged.
48. The marker shows the time of its last update on the map, as in Lysk's deck. Camera moves start 80 ms after an update, once the bottom sheet's new height is known; before, a resize could stop the animation half way.
49. Ukrainian questions are spoken by the on-device voice (decision 43) when it is loaded and the text has only characters it knows; otherwise the system voice speaks, as it still does for English and French (Alex, 20 Nov: "Yes, hook it in"). The voice starts loading when Kyiv is selected or a Ukrainian report arrives: about 77 MB the first time, with nothing on screen to show it. It is unlocked by the same tap that unlocks `speechSynthesis`, only in Kyiv, so Vincennes behaves as before. Checked in desktop Chromium with typed reports; not yet on a phone.
50. The live site serves the voice model itself: `TTS_BUNDLE_MODEL=1` is set on Vercel for production and preview (Alex, 20 Nov: "Yes, bundle it"; settles the open point of decision 45). Each deploy's build downloads the 77 MB model from Hugging Face, checks its SHA-256 and publishes it at `/tts/`. Vercel's limits page states no size cap on files a build creates; its 100 MB Hobby cap is for source files uploaded by the CLI, and the model is never one because `public/tts/` and `models/` are git-ignored. Confirmed on 20 Nov with production deploy `dpl_2pXfx43YgifTzzsYRrYkkxtDdqjy` (commit `384d7aa`, CLI deploy; the project is not connected to GitHub, so a push alone does not deploy). The build log shows the model "downloaded and verified", the live file has the pinned SHA-256, and `/tts-lab` on the live site loaded it in 19.5 s on first visit and matched Piper on all 4 self-check sentences. If a later deploy fails because of it, remove the variable.
51. A report can carry a stated distance (`distance_m`) and a compass direction of travel (`direction`, eight points), and a place can be north-east, south-east, south-west or north-west of the speaker (Alex, 20 Nov: "Yes, add it"). The model only copies a distance that was said and converts its unit; it never works one out from a time or a number of streets. A distance over 20 km is dropped.
52. With a distance, "200 m south of X" pins 200 m out from X's edge instead of the fixed 100 m, which stands when no distance is said. The circle is 0.4 × the distance, 50 m at least: one compass word in eight is good to ±22.5°, which is 0.38 of the distance sideways.
53. "200 m from X" with no side given keeps the pin on X and widens the circle to X's extent plus 1.25 × the distance (a said distance is taken as good to a quarter). A direction of travel in the same report means the distance was how far they moved, so the circle is not widened.
54. Dead reckoning: a distance and a compass direction with no place ("moved 300 m north", "300 m north of my last position") move the marker from the last position, however old it is. The circle is the last position's circle plus 0.4 × the distance, so it grows each leg, and the position is an estimate (≈, as in decision 47). With no last position the app asks for a place; with only a distance or only a direction it asks for both. The phone's GPS is still never read.
55. "Moved 200 m towards X" goes 200 m along the leg, never past X, with the last position's circle plus a quarter of the distance (50 m at least); without a distance decision 46 stands. "Moved 300 m east on rue X" moves the reckoned point onto that street. A place that cannot be found does not stop a move that states its distance and direction: it is reckoned and the log says the place was ignored.
56. The client now sends the last position's circle (`radius_m`) with every report, so a reckoned position starts out as unsure as the one it came from. `uncertainty_m` is unchanged and still only sent for estimates.
57. The longer extraction prompt costs no measurable time: old and new prompt on the same 8 sentences, 16 calls each, alternating (20 Nov): median 834 ms against 843 ms. Either prompt has slow single calls (old up to 1.9 s, new up to 3.1 s in that run), and one call through the app took 8.3 s; the 10 s timeout is unchanged.
58. The transmitter is a native app (Expo SDK 58, React Native) in `transmitter/` that stands in for a field radio. Where Lysk's audio really comes from is still an open question, so the coordinator takes the same report from the web page, this app or a scripted clip, and nothing else depends on the answer.
59. It is a native development build, not Expo Go: on-device transcription and an open microphone both need native modules, so starting in Expo Go would mean switching later. iPhones get it by cable from the Mac (no paid Apple account); Android by install file.
60. One utterance format (audio or text, call sign, start and end time, sequence number) with swappable sources: scenario clip and hold-to-talk now, an open microphone that cuts at pauses later (Alex, 20 Nov: clips first, open microphone as a later migration).
61. Simulated speech is a clip sent down the same path as recorded speech, not audio played into the microphone. It is silent and repeatable and works in a simulator; only the microphone capture itself is left for live testing.
62. Scenarios are data (`scenarios/*.json`): each step has the words, a time offset and the answer it should get. A run therefore gives a score, and the same file can later be rendered as one continuous track for the open microphone. Clips are made with macOS voices and committed.
63. The app sends `session`, `callsign` and `seq` with every report. The server ignores them until it stores reports, so the transmitter will not need to change when it does.
64. Uploads use expo-file-system's `File`: Expo 58's fetch rejects React Native's old `{ uri, name, type }` form part ("Unsupported FormDataPart implementation").
65. One screen, so no Expo Router, despite the template's advice. The template's MIT licence file is removed: it covers Expo's template, and this repo's own terms are not settled.
66. The iOS build needs a UTF-8 locale (`LANG=en_US.UTF-8`), or CocoaPods fails before compiling.
67. The transmitter's reply types are imported from `lib/geo/types.ts` as types only, so a change to the server's reply shows up as a type error in the app instead of at run time.
68. `AGENTS.md` is the one instruction file for every coding agent: Claude Code and Codex both read it, and one teammate uses Codex (Alex, 20 Nov). There is no `CLAUDE.md`; project rules go in `AGENTS.md`, or `transmitter/AGENTS.md` for the app, which now says where the app departs from the Expo template's advice (no Expo Router, no EAS).
69. `docs/DESIGN.md` is the team's design document: the challenge, our approach, what is built, the contracts between parts, the work ahead and open questions. A shareable copy for people without the repo is kept in Claude Docs; the repo file wins if they differ.
70. `.env.example` lists every environment variable the code reads, with no values, and is the one `.env*` file git tracks.
71. Speech-to-text in the transmitter is switchable: the server (Mistral) or Whisper on the phone (`whisper.rn` 0.7.4) with `ggml-base-q5_1` (56 MB) or `ggml-small-q5_1` (181 MB), downloaded once from Hugging Face into the app. In a phone mode only the words are sent, as the server's existing text input (Alex, 20 Nov: on-device speech-to-text, download approved).
72. Measured on 20 Nov in the iPhone simulator on the 9 scenario steps (synthetic voices): server 9 of 9; phone small 8 of 9 with or without hints; phone base 8 of 9 with place-name hints and 4 of 9 without. Every miss was a question or "could not place", never a wrong pin. Raw results in `scenarios/results/`.

75. Scenario clips are committed twice, compressed (m4a, for the server) and uncompressed 16 kHz mono (wav, for Whisper, which reads nothing else). On iOS the microphone records uncompressed audio in phone modes; on Android the microphone still goes through the server.

77. `whisper.rn` needs the `buffer` package at run time and a `paths` entry in the transmitter's tsconfig, because its package.json has no root entry in its exports map.
78. The transmitter talks to the coordinator on the computer it was loaded from, port 3117, by default (Alex, 20 Nov: "it has to talk to the coordinator on this mac"). The live site is one tap away, and a light shows whether the coordinator answers.
79. First real-phone run, 20 Nov: iPhone 13 mini through the coordinator on the Mac, Kyiv scenario twice, 10 of 10 steps as expected, round trip 1.2 to 1.9 s with server speech-to-text. On-phone speech-to-text is still unmeasured on a real phone.
80. A development build needs the phone and the Mac on one network that lets devices reach each other; when the Mac changed networks the app could not load. A build with its code packed inside was made but not installed (Alex: not wanted).
81. A phone opens the transmitter with the Mac's network name (`<name>.local`), not a numeric address. The first phone runs worked only over the USB cable's temporary address and broke when that address changed ("no answer from the coordinator"); the name survives that and needs no shared Wi-Fi.
82. Scenario clips are sent silently by default; an option plays each clip aloud first, for an audience. The phone's own speech ignores the ring switch. Send failures and the coordinator's address are written to the dev-server log so a phone can be diagnosed from the Mac.
83. `PROVIDER_MODE=local` makes the coordinator call nothing outside the computer: intent extraction goes to Ollama on the same machine with the same prompt and schema, and audio gets a clear error until there is speech-to-text on the computer, so local mode never falls back to Mistral. Ollama runs with `OLLAMA_NO_CLOUD=1`, so it cannot hand a request to its hosted models [42] (Alex, 20 Nov: a model on the MacBook to replace Mistral, for the fully offline mode).
84. The local extraction model is Ministral 3 3B (`ministral-3:3b`, 3 GB, Apache 2.0), overridable with `LOCAL_EXTRACT_MODEL`. Measured 20 Nov on the MacBook (M1 Pro, 32 GB), 9 scenario texts through extraction and the resolver: Mistral Small 9 of 9, median 0.8 s; Ministral 3 8B 8 of 9, 5.1 s; Ministral 3 3B 8 of 9, 2.0 s. The 8B alone is over the 4 s target. Both miss "Golden Gate" with a question, never a wrong pin (Alex, 20 Nov: try 3B).
85. In local mode the server loads the model and each area's prompt in the background when it starts (`instrumentation.ts`), because the first report otherwise waited about 9 s for the model. Local extraction gets 25 s instead of 10 for the same reason.
86. Same-name streets are no longer merged into one. The gazetteer build joins pieces of one name within 150 m, or in the same town up to 1 km apart; anything else is a separate street that carries its town (the OSM admin area at the area's `townAdminLevel`: commune 8 in France, city 4 for Kyiv, looked up with one Overpass query). Asking back names the towns, or the distances when the towns do not tell them apart. A unique name keeps its id (`street/<name>`); shared names get `street/<name>/<town>`. Contract change, additive: optional `town` on `GazetteerFeature` and `Candidate` in `lib/geo/types.ts`; the transmitter needs no change. Rebuilt 20 Nov: Vincennes 911 places, 16 names now two streets each (e.g. Rue Gambetta in Fontenay-sous-Bois and in Montreuil); Kyiv unchanged at 2,112. A town answer with no towns, as one Overpass mirror gave, fails the build instead of writing a file without them.

The design docs are Markdown in `docs/`, one file per topic (overview, architecture, contracts, plan, gazetteer, open questions, known gaps, glossary), indexed in `docs/README.md`, plus `CONTRIBUTING.md` at the root. Setting up a computer is one step-by-step file, `docs/setup.md`, written so Claude Code or Codex can follow it on a teammate's machine: a check after each step, steps that need the person marked, and the agent never handles the Mistral key. `AGENTS.md`, `CONTRIBUTING.md`, the docs index and both READMEs point to it (Alex, 20 Nov: "local setup instructions that claude/codex can follow").

The transmitter's iOS bundle ID and Apple team can come from the environment (`TRANSMITTER_BUNDLE_ID`, `APPLE_TEAM_ID`, read in `transmitter/app.config.ts`), because each teammate signs with their own free Apple ID and `dev.voicetomap.transmitter` already belongs to Alex's team. The setup guide sets up offline mode first, with no key, and hosted mode only for someone who has one; the docs, `.env.example` and the server's messages say so, and an agent never waits for a key. Hosted mode stays the default when `PROVIDER_MODE` is unset, and the server warns at start when it has no key (Alex, 20 Nov: a teammate's Codex got stuck on docs that still said the key was required).
98. The receiver is a view-only page at `/receiver?session=<code>` (default `demo`), laid out for a laptop or projector: one coloured marker per call sign with its name, time, circle, trail and movement arrow; a list of units; a feed of reports; open questions with their choices numbered on the map; a replay bar (Live, play at 1×, 10× or 30×, a time slider); and markers that dim after 3 minutes of silence. The phone web page stays at `/` until Alex decides when to remove it (Alex, 20 Nov: it is "the web view of the transmitter that we no longer need").
99. The coordinator saves every report that names a `session` as one entry in an append-only log per session, with where it leaves the speaker worked out on the server (`lib/reports/position.ts`), so the receiver and a replay only read positions. The receiver polls `GET /api/sessions/<code>?after=<n>` every second and rebuilds the map with one pure function (`foldLog`), so a replay is the log read up to a moment. Contract change: `POST /api/report` now uses `session`, `callsign` and `seq`, and its reply carries `report_id` when the report was saved. Reports with no session (the web page) are not saved.
100. A tapped choice now reaches the server: the transmitter sends `POST /api/answer` with `{ session, report, choice }` (`choice` null for "none of these"). Before, a choice only moved the phone's own marker, so the receiver would have shown "awaiting answer" for ever. Contract change. The first answer to a question stands, and a late answer does not move a marker that has a newer fix.
101. Reports are stored behind one interface (`lib/reports/store.ts`): a JSON-lines file per session in `.data/sessions/` (ignored by git), the default outside Vercel; or nothing on Vercel, where files are neither kept nor shared between instances, and the receiver says so. The demo's coordinator runs on the Mac [78], so the file is the demo's store, online or offline. A hosted store for the live site is not chosen yet.
102. A report sent twice (same session, call sign, `seq` and client time) is saved once. `seq` alone is not enough: the transmitter's counter restarts on reset and is shared by every call sign in a scenario.
103. Next.js's development badge is off (`devIndicators: false`): the demo runs `next dev` on the Mac, and the badge covered the receiver's Live button. Compile and runtime errors still show.
104. The question's language is checked against the letters in the transcript (`checkLanguage` in `lib/providers/extractor.ts`): with no Cyrillic letters the report is not Ukrainian unless speech-to-text said so, with only Cyrillic letters it is Ukrainian, and with both the model's label stands. In offline mode the 3B model labelled English Kyiv reports as Ukrainian when the place was one of its prompt's Ukrainian examples ("I'm at Khreshchatyk.", "Moving towards Saint Sophia Cathedral."), every time; the question then came back in Ukrainian and the phone page spoke it with the slow on-device voice (Alex, 20 Nov: "Yes, both"). The cost: Ukrainian that Whisper on the phone writes in Latin letters (decision 76) now gets an English question, because the transmitter sends only the words. The model still writes some English names in Cyrillic ("Golden Gate" became "Золотих воріт"); that is not fixed.
105. The Ukrainian voice runs in a worker, through onnxruntime-web's proxy mode (`ort.env.wasm.proxy = true`), which starts the worker from its own script in `/ort/` (Alex, 20 Nov: "Yes, both"). Before, starting the model froze the page for 1.3 s and each question for 0.7 to 1.0 s (desktop Chromium on an M1 Pro, 20 Nov). Now the longest freeze is about 20 ms, speech takes the same time (4.1 s of speech in 0.66 s), and `/tts-lab`'s self-check still matches Piper on all 4 sentences. Phones are still unmeasured; `/tts-lab` shows the time on any device.
106. The speaker's language is pinned on the device, not guessed (Alex, 20 Nov: "a pinned setting instead so there is no ambiguity"). `POST /api/report` takes an optional `language` field (`en`, `fr`, `uk`), a deliberate contract change that older clients can ignore. With it, the intent and the reply take that language as is, so the question's language and voice follow it. Without it, the model's label is checked as in decision 104. 107. Missions are built as planned in `docs/plan.md`, with the four proposed choices (Alex, 20 Nov: "Yes, build it"): a start point set at the base plus a spoken check-in; the coordinator keeps each unit's last position for reports in a mission; ending a mission keeps it for replay, so "reset" is ending one and opening another; phones join from a list of open missions, with no QR code. The code and the endpoints keep the word "session"; the screens say "mission".
108. Contract change: a report that names a `session` needs an open mission, and gets 404 for an unknown code and 409 with `ended: true` for an ended one. In a mission the coordinator uses the mission's area and the unit's last position from the log (its latest fix, else the start point) and ignores the `area` and `lastPosition` the phone sent, so the receiver and the resolver agree on where a unit is. Reports with no session work as before. The log gains `mission`, `join` and `end` entries. `lib/reports/types.ts` now imports with relative paths, so the transmitter can import its types, type-only, as it does `lib/geo/types.ts` [67].
109. New endpoints: `GET /api/sessions` lists missions, open ones first; `POST /api/sessions` opens one with `{ area, name?, start? }`, where `start` is a gazetteer place id, so no coordinates come in and no model makes them; `POST /api/sessions/<code>/join` with `{ callsign, device }`; `POST /api/sessions/<code>/end`; `DELETE /api/sessions/<code>` for an ended mission; `GET /api/places?area=&q=` to pick a start point by name. Codes are `<area>-<n>` and never reused, deleted ones included, so a phone that remembers a code cannot rejoin a different mission. An answer to an ended mission gets 409.
110. A start point is a circle of 300 m around the gazetteer place, or the place's own size if larger, and it is an estimate: it reaches the resolver with `uncertainty_m`, so it never settles a choice between nearby places on its own [47]. It is an assumption, so the receiver draws no trail from it.
111. One phone per call sign in a mission: a second phone gets 409 with `taken: true` while the holder has been heard in the last 3 minutes, and may take the call sign over after that. A call sign that reports without joining (a scenario's second call sign, sent from the same phone) joins with that report. Call signs are stored in capitals, so "alpha 1" and "ALPHA 1" are one unit.
112. Deleting a mission moves its file to `.data/sessions/deleted/` rather than removing it, and only an ended mission can be deleted. A check and the write it leads to (is the call sign free, was this report saved already) run one at a time per mission in the coordinator's process (`withSessionLock`); the coordinator is one process on the Mac.
113. The receiver now opens and ends missions, so it is no longer view-only [98]: a Missions menu (new mission with area, name and an optional start point; open and ended missions; delete) and an End mission button with a confirmation. With no `?session=` it shows the newest open mission, or opens the menu when none is open. A question still open when its mission ends is closed as not answered.
114. The transmitter joins a mission before it reports: a card lists the coordinator's open missions (picked when there is only one) and the call sign, and the talk button says "Join first" until then. The phone keeps its own id and the mission it joined in `transmitter.json` in the app's documents and rejoins on start. Its reachability check now reads `GET /api/sessions` every 5 seconds, so it also notices a new or ended mission. A coordinator that keeps no record (the live site) offers no missions, and the phone reports with no session, as before. Scenarios are narrowed to the mission's area.

118. The lightweight branch uses a plain Node controller and custom phone and controller browser pages. Ollama and the deterministic gazetteer resolver remain. Native builds, framework packages, hosted AI providers, audio models on the phone and bundlers are removed (Brian, 20 Nov).
119. Phone reports are typed or dictated through the installed keyboard. The application accepts text only. Phone dictation privacy, language support and offline availability depend on the phone. Received, processing, result, failure and clarification feedback are shown on the phone, with selectable place buttons and optional system read-aloud.
120. The browser contract is replaced with the endpoints in docs/contracts.md. Mission join codes and private unit tokens identify phones. Controller operations are loopback-only. Submitted reports are acknowledged before local inference. Request ids deduplicate retries; newer reports and ended missions supersede old results and questions.
121. The lightweight map draws bundled OpenStreetMap streets and landmarks with browser SVG. It includes units, uncertainty circles, trails, movement headings, candidate numbers and replay without a tile service. Mission events are saved under .data/lightweight; no implicit migration of previous mission files is performed.
122. The application has no npm dependencies. Node supplies its HTTP server, storage, tests and syntax validation. The README is a fresh user guide with all runtime requirements and install, build and run commands; detailed interfaces and decision records stay outside it.
